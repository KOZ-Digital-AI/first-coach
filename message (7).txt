FIRST COACH / БІРІНШІ БАПКЕР
Every child deserves a great first coach.
FIRST COACH — бесплатная open-source платформа, которая помогает человеку самостоятельно развивать спортивные навыки по проверенным методикам профессиональных тренеров.
Проект создаётся KOZ AI к 60-летию Кайрата Боранбаева.
Но проект не является цифровым памятником Кайрату Боранбаеву.
Смысл подарка:
KOZ AI создаёт для него инфраструктуру.
Кайрат Боранбаев открывает её людям бесплатно.
На старте — футбол.
В дальнейшем архитектура должна позволять добавлять любые виды спорта.
1. Главная идея
Сегодня качество спортивного обучения сильно зависит от того:
где родился ребёнок;
есть ли рядом хорошая академия;
могут ли родители оплачивать тренера;
есть ли у школьного тренера качественная методология;
знает ли сам ребёнок, как правильно тренироваться самостоятельно.
При этом огромное количество профессионального coaching knowledge уже существует у тренеров, академий, федераций и спортсменов.
Проблема в том, что оно фрагментировано и плохо масштабируется.
FIRST COACH должен превратить эти знания в открытую систему:
Expert knowledge → structured methodology → skill graph → assessment → personal roadmap → training → progress → reassessment.

3. Главное отличие: Skill Graph
Не строить продукт вокруг каталога тренировок.
Основой должен быть Skill Graph.
Каждый спорт раскладывается в дерево навыков.
Например:
Football
→ Ball Control
 → Basic touches
 → Inside/outside
 → Sole control
 → Direction change
 → First touch
 → Receiving under movement
→ Passing
 → Short passing
 → First-touch pass
 → Weak-foot passing
 → Passing accuracy
 → Moving pass
→ Dribbling
→ Shooting
→ Coordination
→ Physical preparation
→ Decision making
У каждого skill node должны быть:
prerequisites;
drills;
tests;
levels;
expected outcomes;
common mistakes;
age suitability;
equipment requirements;
safety notes.
То есть пользователь не просто «делает тренировку».
Он движется по карте навыков.
4. AI Coach
AI не должен самостоятельно придумывать спортивную методологию каждый раз.
Это критически важно.
AI работает поверх подтверждённой базы знаний.
Логика:
User profile + current skills + goals + constraints → AI → approved drills → personal training plan.
AI может:
объяснить упражнение проще;
подобрать упражнение;
адаптировать тренировку;
уменьшить/увеличить сложность;
собрать программу;
анализировать прогресс;
отвечать на вопросы;
переводить методики;
превращать экспертные документы в структурированные данные.
Но AI не должен бесконтрольно придумывать новые упражнения для детей.
5. AI VIDEO COACH
Это отдельная сильная функция.
Пользователь выбирает навык:
Analyse my dribbling
Ставит телефон.
Записывает 10–30 секунд.
Загружает видео.
Система анализирует видео по rubric данного skill.
Например:
Inside / Outside Dribbling
System looks at:
body position;
number of touches;
ball distance;
use of both feet;
rhythm;
control;
change of direction.
Результат:
Your analysis
Ball control
7/10
Body positioning
6/10
Weak foot
3/10
Consistency
7/10
Focus next
Your weak foot is currently limiting your movement.
Recommended next
Weak-foot inside touches
Alternating touches
Slow slalom
Repeat assessment after 3 sessions
Главная функция анализа — не сказать:
«Ты играешь на 63/100».
А ответить:
«Что тебе тренировать следующим?»
6. Видеоанализ: техническая архитектура
Для MVP не пытаться строить proprietary computer vision model.
Можно начать с:
Video
↓
frame extraction
↓
pose detection
↓
AI vision analysis
↓
skill-specific rubric
↓
structured feedback
MediaPipe уже может определять 33 landmarks тела и рассчитан в том числе на real-time fitness use cases. Это можно использовать как базовый pose layer.
Но для футбола одного pose estimation недостаточно — нужно видеть ещё и мяч.
Поэтому архитектура должна предусматривать:
Person tracking + pose estimation + ball/object tracking + multimodal analysis.
Важно:
на запуске видеоанализ обозначить как Beta.
Он не должен быть обязательным для использования продукта.
7. Skill Tests
В v0.1 основной assessment лучше строить не только через AI-video, а через простые измеримые tests.
Например:
Juggling
Maximum consecutive touches.
Wall Passing
Successful passes in 60 seconds.
Ball Mastery
Touches in 30 seconds.
Slalom
Completion time + errors.
Weak Foot
Successful passes / attempts.
Пользователь записывает результат.
Получаем объективный baseline.
Через 7/14/30 дней повторяем тест.
Показываем:
Your previous result: 14
Today: 21
+50%
Это даёт пользователю реальное ощущение развития.

9. AI INGESTION
После загрузки AI сам превращает материал в стандарт FIRST COACH.
Например тренер загрузил 40-страничную методичку.
AI:
извлекает упражнения;
определяет skills;
определяет возраст;
определяет difficulty;
создаёт drills;
находит prerequisites;
структурирует progressions;
добавляет safety fields;
создаёт draft Skill Graph;
отправляет человеку на подтверждение.
Это особенно важно для следующего этапа с Академией «Кайрат».
Мы не будем «дообучать модель на PDF».
Правильнее:
Academy methodology → structured extraction → expert validation → FIRST COACH Knowledge Base.
После этого AI Coach использует уже утверждённую методику.

Проект состоит из двух открытых частей.

Web/mobile application.

B. OPEN SPORT COMMONS
Структурированная открытая база спортивных знаний.
Не просто JSON с тренировками.
Это должен стать открытый формат описания спортивной методики.
Например:
Sport

    ├── prerequisites
    ├── levels
    ├── drills
    ├── assessments
    ├── progressions
    ├── regressions
    ├── age ranges
    ├── equipment

Мы создаём не только продукт.
Мы создаём public infrastructure.
13. Content licensing
Для methodology layer использовать открытую лицензию вроде:
CC BY-SA
Это позволяет людям:
использовать;
переводить;
улучшать;
распространять;
при сохранении attribution и открытости производных материалов.
Для software отдельно выбирается open-source license.
Не копировать упражнения и видео FIFA, UEFA и коммерческих сервисов в нашу базу только потому, что они доступны онлайн.
Контент FIFA, например, защищён авторскими правами и не становится open source автоматически.
Стартовый контент должен быть:
создан нами;
создан приглашёнными тренерами;
передан с разрешением правообладателя;
находиться под совместимой открытой лицензией.

21. Privacy / children
Так как продукт предназначен детям, privacy должна быть частью архитектуры с первого дня.
По умолчанию:
видео пользователя private;
никакой публичной ленты детей;
никаких личных сообщений между взрослыми и детьми;
никаких публичных профилей ребёнка;
raw video можно удалять после анализа;
пользователь отдельно разрешает использовать видео для улучшения моделей;
данные не используются для рекламы.
Для детского спорта safeguarding нельзя прикручивать потом: FIFA отдельно рассматривает защиту детей как обязательную часть футбольных программ.
